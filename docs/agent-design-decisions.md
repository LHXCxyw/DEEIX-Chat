## 1. 产品与文件模型

普通持久化聊天无需先建项目即可进行文件任务，提供会话专属持久化工作区，可提升为正式项目。正式项目多个会话共享工作区。

第一版覆盖代码、文本、配置文件及 ZIP 项目，不承诺任意 Office/PDF 原格式编辑。上传附件默认只读，原件不可变；用户明确要求编辑后才创建工作副本。ZIP 默认不自动解压，必须明确授权。允许编辑不等于允许执行代码。

任务启动时提供独立权限项：编辑文件、解压指定 ZIP、运行项目代码、浏览当前项目、公网浏览。明确用户指令可以预选，但用户须确认任务授权。在已授权范围内自主执行低风险操作，不逐条确认。授权绑定任务和工作区，不跨任务复用。

项目提升保留同一工作区和历史，不复制文件；提升时不得有运行中的修改任务。第一版不自动合并到已有项目。

单文件修复直接提供文件下载，多文件同时提供 ZIP。交付内容固定为交付时版本，不随后续编辑变化。交付物随所属会话或项目保留并计入存储配额，访问链接过期后可登录重新下载。删除生命周期按第 7 节执行。

临时聊天首版仅保留问答，持久化编辑和执行需先转为普通会话。

## 2. 授权、执行、网络与秘密

项目代码只能在隔离执行环境中运行，禁止直接在 Go 网站宿主机执行。执行容器默认无出站网络，使用管理员预构建镜像及离线依赖；缺失依赖报告验证受阻，不自动联网。首批支持 Node.js/TypeScript 与 Python，Go 后续扩展。

不提供真实秘密。部署、推送代码、访问生产资源、使用秘密默认拒绝。批量删除等高风险操作需额外授权，后端独立校验。Agent 默认不得调用未纳入安全策略的外部 MCP，不因此全局关闭普通聊天 MCP。

普通聊天不创建执行容器。Docker 不可用时允许编辑交付，但必须标记未运行验证，禁止声称测试通过。

## 3. 并发、证据与统一预算

同一工作区一个修改型任务运行，其余排队。人工保存检测版本冲突，不静默覆盖；任务期间工作区版本变化时暂停结果合并。不同工作区受全局和用户配额限制。

修改完成与验证通过分开记录。验证证据绑定文件版本、命令、退出码与日志；文件改变后旧结论失效。不得删除测试、弱化断言或跳过检查冒充修复；确需修改测试需披露原因。浏览器截图或没有控制台错误不单独构成功能正确的证明。

默认限额：

| 范围 | 上限 |
|---|---|
| 每用户运行中的修改任务 | 1 个 |
| 全站执行环境 | 2 个 |
| 单代码执行环境 | 2 CPU、2 GiB 内存、128 PID |
| 单工作区 | 1 GiB，强制磁盘配额 |
| 单次命令 | 120 秒 |
| 单任务 | 30 分钟、32 次模型请求、128 次工具调用 |

管理员可收紧，现有余额和配额继续有效。达到预算保存检查点，确认继续不重置历史消耗；后续增加预算必须是明确授权的增量，不能把恢复当成预算归零。无法落实资源限制时拒绝执行。

说明：表中为设计上限；当前隔离命令实现的单次资源上限更保守，具体数值以实现为准。

## 4. 浏览器与公网授权

首版使用 Playwright + Chromium，默认仅访问当前任务绑定的项目预览。支持浏览网页、点击、填写表单、截图、读取控制台错误、检查失败请求和下载文件。暂不开放任意 JavaScript 执行、原始 CDP 或个人浏览器控制。

公网授权绑定任务、允许域名与有效期，不是互联网通行证。重定向、子资源、WebSocket、弹窗和下载受相同规则控制；授权不能放开宿主机、元数据接口或未授权内网与管理页面。执行容器不因浏览器公网授权而联网。

登录后操作另行授权，绑定站点及具体动作。首版只支持专用测试账户的临时登录会话，不保存密码，不接入个人浏览器，不向模型提供凭据；不得操作生产支付、部署或生产数据。无法安全建立登录态则保持不可用。

浏览器独立默认限额：

| 项目 | 上限 |
|---|---|
| 每任务浏览器实例 | 1 个 |
| 同时打开页面 | 2 个 |
| CPU / 内存 | 1 CPU / 1 GiB |
| 累计活跃运行时间 | 10 分钟 |
| 单次操作 | 30 秒 |
| 单个下载 / 每任务累计下载 | 50 MiB / 200 MiB |

浏览器计入统一 Agent 预算，同时采用独立限额。调度器按浏览器与代码环境合计资源准入；不得将浏览器时间擅自换算成 Token 收费。下载按不可信附件保存，不自动执行、解压或导入工作区。

## 5. 执行恢复与真实取消

持久化操作 ID 和状态。安全操作可重试，文件修改幂等。执行结果不确定的命令禁止盲目重跑；恢复前核对执行记录、容器状态与文件版本。恢复执行不同于恢复进度流。

取消任务必须终止实际执行进程和浏览器，而非仅停止等待或更新界面。保留已持久化修改，未同步内容隔离保留，不直接覆盖工作区。

## 6. 审批生命周期

审批绑定操作 ID、规范化参数、工作区版本及权限范围，最长有效 24 小时。参数或相关文件版本改变即失效。

等待审批时停止命令和浏览器并释放运行配额，保留检查点。等待时间不计活跃执行预算。恢复前重新校验权限、版本与资源；外部账户操作不因重启自动重试。

## 7. 删除与版本清理

删除会话停止其相关任务，清理会话专属工作区，不误删项目共享文件。删除项目先撤销访问并禁止新任务，终止执行环境，再异步清理专属文件、索引及交付物。

文件版本在所属资源存续期间保留；用户显式删除所属项目或会话时允许清理其独占历史版本。其他有效对象仍引用的内容不得物理删除。

清理须幂等、可重试、可观测，失败可查看与重试。对应内容实际清理完成后才释放存储配额。不以仅软删除替代实际清理要求。

当前实现只完成删除停止屏障与写入屏障，物理清理 worker 尚未实现，详见进度报告第 4.4 节。

## 8. 领域词汇

- 会话工作区：普通持久化会话专属的可持续编辑文件集合，无需先建项目，可提升为项目工作区。
- 项目工作区：正式项目拥有的可持续编辑文件集合，同一项目多个会话共享当前文件状态。
- 执行环境：为文件任务提供隔离运行与验证能力的临时环境，不是文件唯一持久化载体。
- 交付物：任务交付给用户的固定版本文件或文件集合，与上传原件区分。
- 执行恢复：中断后从已确认状态继续任务，不等同于重新订阅进度流，也不意味着重复执行不确定副作用。

## 9. 实施顺序与验收范围

1. 复核当前代码、工作区与 Run 数据模型，定位迁移和兼容边界；复用现有渠道、计费、认证、文件存储与工具循环，不重建平行系统。
2. 实现会话工作区、附件工作副本、独立任务授权、文件版本冲突与固定版本交付，完成上传—编辑—下载闭环。
3. 实现持久化操作状态、审批与检查点、任务排队及预算；保证幂等、取消和恢复语义。
4. 实现离线隔离命令与进程管理、文件同步和真实验证证据，打通失败—修复—重跑闭环。
5. 实现 Playwright/Chromium 隔离浏览器、项目预览、受控公网及账户授权、下载与证据呈现。
6. 实现删除清理生命周期与资源回收，补齐前端状态、日志、权限交互和错误提示。
7. 分阶段执行真实回归、权限、冲突、重启、取消、配额、网络、清理及端到端验收；报告实际结果和未验证项，不将静态检查或模拟测试当作 Docker/浏览器实测。

## 11. 已废弃方案与替代

以下方案曾出现在早期设计或实施记录中，现已被替代，不再具有实施约束。

| 废弃方案 | 替代方案 |
|---|---|
| 内部 registry 分发执行镜像并读取 RepoDigest 生成白名单 | `app` 读取本地构建镜像 ID，校验 runner 标签后注入白名单 |
| 独立 DinD／嵌套 Docker daemon | 宿主 Docker 直接创建任务容器，只保留一层容器隔离；远程场景使用独立执行节点 |
| 七容器常驻拆分 | 常驻 `app`、`postgres`、`redis` 三个，配置初始化与镜像构建为一次性容器 |
| seed 导入执行镜像 | Compose build-only 服务构建本地镜像，`app` 直接校验镜像 ID |
| `runtime.env` 注入运行时配置 | `app` 入口自行读取镜像 ID、校验标签并注入环境变量 |
| `chrome://sandbox` 页面自检 | 实际渲染空白页、执行脚本并截图；seccomp 策略为 `moby-27.5.1-chromium-userns-v2` |
| `--ipc=none` 等旧浏览器隔离参数 | `--ipc=private` 独立共享内存；不开启 `--no-sandbox`、`SYS_ADMIN` 或 seccomp unconfined |
| 旧权限归一化路径：前端显式 `edit_files` 单次授权、`execute_code` 独立勾选、后端按字段归一化 | 前端只传 `mode`，后端按 `manual`／`auto`／`full` 归一化为允许文件编辑与代码执行，仅审批方式不同 |
| “浏览器仅有策略基础、生产请求固定 503”的旧状态描述 | 断网项目浏览器与静态截图已实现；公网浏览器仍为未部署，能力状态区分 `project_browser` 与 `browser` |

## 12. 其他已确认决策记录

以下内容与 Agent 架构无关，保留原决策结论。

### 12.1 Web 与后端同步：D1 后端轨迹摘要

消息列表仅在显式 `trace=summary` 时为成功助手消息生成摘要；新增 `detailOmitted`、完整轨迹响应与认证路由 `GET /messages/{id}/trace`。详情复用当前用户归属约束，未知或他人消息返回 404；blocked、非助手或无轨迹返回 `processTrace: null`。本地摘要保留 text 事件身份、轮次、顺序和时间，思考与中间正文按 rune 保留前 80 字符，工具摘要删除大字段但保留预览、身份、状态与耗时。

### 12.2 D2-B：重试菜单

移除助手回复重试时选择其他 reasoning effort 的菜单与单次请求 override；点击重试使用当前 composer 的 model/options。普通 reasoning 配置、消息 reasoning 元数据归一化与 composer 控件保持不变。

### 12.3 D3—D6

- D3-A：保留本地“按协议编码能力决定原生附件”的策略；新增 `nativeInputPolicy.readsWithoutExtraction`，仅满足原生 PDF 条件的提取失败文件继续发送，失败音频/视频仍排除。
- D4-A：`UploadFileInput` 新增可选 `MaxBytes`，平台生成图片统一使用 50 MiB 上限，并在计费会话开始前预检生成媒体存储配额。
- D5-B：`settings/duplicates.go` 对同一 namespace+key 按“被修改过优先、更新时间较新、ID 较小”确定性选行；启动时删除重复行并在事务内重建索引，修复失败只告警不阻断启动。
- D6-A：版本同步新增 `web-backend` 模式，契约生成不再改写桌面端 `package.json`、Tauri 与 Cargo 版本。

### 12.4 M1—M5

- M1：新增 `ultra` 推理档位（仅 OpenAI 格式可声明）与 `ReasoningOwnedOptionPaths`，被思考强度翻译接管的原生参数不再单独展示。
- M2：个人渠道导入链接支持 v2 多条目、条目数上限、重复条目校验与批量确认界面。
- M3：新增共享 `isImeComposingKeyEvent`，消息编辑按配置的发送快捷键保存并跳过输入法组合中的 Enter。
- M4：附件失败原因锚定整卡 Tooltip；Markdown 美元公式按 Pandoc 规则重写；新增图片 UI block 与画廊。
- M5：手工补充 `ultra` 联合类型；README 说明 Web 与后端同步上游版本，桌面端另行升级。

### 12.5 允许指定来源 iframe 嵌套

新增 `security.frame_ancestors`（环境变量 `SECURITY_FRAME_ANCESTORS`），取值为 CSP `frame-ancestors` 语法。留空、`none` 或非法内容保持 `X-Frame-Options: DENY`；`'self'` 发送 CSP 与 `X-Frame-Options: SAMEORIGIN`；来源白名单只发送 CSP。公开文件内容响应继续使用 `frame-ancestors 'none'`。
