# 0003 - 媒体分发采用签名链接直连 + CDN 边缘缓存

日期：2026-09-14
状态：已接受

## 背景

所有文件媒体（聊天图片、侧边栏缩略图、生成图片/视频）此前统一走"带 `Authorization` 头的 fetch → blob URL"链路。生产环境服务器出口带宽仅 19.3Mbps（约 2.4MB/s），前端列表页并发拉取原图全量字节，导致单图排队至分钟级；CDN 边缘回源超时（60~100s）切断 H2 流后浏览器批量报 `net::ERR_HTTP2_PROTOCOL_ERROR`。

可缓存的每一层都形同虚设：鉴权响应带 `Cache-Control: private, max-age=60` + `Vary: Authorization`，CDN 按规范零缓存，浏览器缓存被 access token 轮换打穿（历史默认 60 秒过期 + 换 token 即整批失效）；文件内容接口无 ETag/304，过期后只能全量重传。项目已有限时签名机制（`filelink`，HMAC 绑定用户与文件，TTL 1 小时），但仅用于上游服务回源，且响应仍按 `private` 头写出，无法被 CDN 缓存。

## 决策

1. **混合访问模型**：生成产物（generated_image/generated_video）、图片缩略图变体、分享与临时会话媒体统一改走**签名内容链接**——后端在 DTO 中内嵌现场签名的 URL，前端用 `<img src>` 直连，不再经 fetch + Authorization；用户上传**原件**保持鉴权 fetch，保留 `Vary: Authorization` 强鉴权。
2. **签名响应按公共不可变内容写出**：签名端点与缩略图端点发 `Cache-Control: public, max-age=31536000, immutable`，使浏览器与 CDN 全链路可缓存；签名参数放 query，由 CDN"忽略 URL 参数"规则保证缓存键稳定（签名绑定同一 fileID，同路径必同内容）。
3. **原件用 ETag（库内 SHA256）+ 304 重验证**：`max-age` 与 access token TTL（默认 24h）对齐，token 轮换后经 If-None-Match 重验证，命中不传字节。保留 `Vary: Authorization`，接受跨账号切换时的低概率重验证成本，换取杜绝同浏览器多账号缓存串读。
4. **图片派生缩略图变体（≤400px / ≤1280px 两档）**：新文件由异步管线生成，存量文件在首次访问时惰性补生成；缩略图同属签名可公开内容。低分辨率变体的公开可读性是显式接受的安全边界（fileID 不可枚举 + 链接短时效）。
5. **文件内容写出层支持 Range/206**：`<video>` 播放与拖动进度条依赖 Range；local 存储天然可 seek，配合 CDN 分片回源，大视频流量主要由边缘承担。

## 备选方案

- **全面签名 URL（含上传原件）**：缓存收益最大化，但把所有用户上传字节都变为"链接持有即可读"，扩大泄露面（否决，仅生成产物与缩略图走签名）。
- **维持鉴权 fetch，仅优化缓存头**：CDN 仍然零命中，19.3Mbps 源站带宽瓶颈无解（否决）。
- **去掉 `Vary: Authorization` 换绝对长缓存**：token 轮换也不失效，但同浏览器切换账号时，已知 fileID 的新账号可能命中旧账号的缓存条目（否决，隐私泄露面不可接受）。
- **WebP 缩略图（cgo）**：比 JPEG 小约 30%，但给 debian/Go 构建链引入 cgo 依赖（否决，接口留 format 参数作后续选项）。

## 后果

- CDN 缓存规则必须只对 `/api/v1/files/` 媒体目录开启"忽略 URL参数"，且严禁开启"强制 CDN 缓存"与"忽略 Vary"（否则鉴权私有内容会被边缘缓存后吐给任意请求者）。
- 签名 URL 在 1 小时时效内为"持有即可读"，泄露窗口已知且可接受；前端对过期 URL 的处理是重新拉取消息/列表获取新链接。
- 缩略图管线为图片类文件新增异步处理步骤；变体缺失时端点同步补生成，首次访问延迟略增。
- 后续若引入 S3 等远端存储，Range 支持需在该存储适配器补透传 Range 头。
