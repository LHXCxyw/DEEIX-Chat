# 2. 项目预览使用统一构建器（取数回调注入）

Date: 2026-10-14

## Status

Accepted

## Context

有两处需要"把项目页面跑起来"：

1. **项目预览工具**：模型在对话内请求运行项目入口页面，前端以受限沙箱 iframe 渲染并把运行信息回传。
2. **分享页文件预览**：匿名访客在分享页查看产出文件的渲染效果。

两者的渲染需求完全一致：按路径读取文件、内联相对资源（CSS/JS/img/@import）、
用 CSP 沙箱文档包裹、iframe 渲染。差异只在**取数**：前者走登录态项目端点，后者走分享域只读端点。

现有的内联与沙箱逻辑散落在 `chat-project-workspace.tsx`（`buildPreviewDocument`、
`buildSandboxPreviewDocument`）中，取数与渲染耦合，无法直接被分享页复用。

## Decision

抽取一个**共享的项目预览构建器**：接收一个"取数回调"（给定相对路径返回文本/DataURL），
负责路径解析、资源内联、沙箱文档构建；两处各自注入自己的取数实现
（登录态项目端点 / 分享域只读端点）。

沙箱原语（`sandbox-document.ts` 的 CSP、iframe 权限、转义、沙箱文档头）为纯函数，直接复用。

## Consequences

- 一处实现、两处复用，避免分享页重复内联算法。
- 取数与渲染解耦，便于各自独立演进鉴权方式。
- 需要先把 `chat-project-workspace.tsx` 中耦合的构建逻辑提取为独立模块（无行为变化）。
