## 同步上游 v0.4.6（sync/web-backend-v0.4.6）

- 基线：Fork 上一轮对齐到上游 v0.4.5（分支 `sync/web-backend-v0.4.5`，HEAD `28fcaf52`），但 `VERSION` 与所有清单仍停在 0.4.4。本轮一次性把版本号对齐到 0.4.6。
- 范围：只同步 `apps/web`、`backend`、共享包与构建基础设施（`Dockerfile`、`.nvmrc`、`Makefile`、`scripts/sync-version.mjs`、CI 的 Node 版本）。不引入 `apps/desktop` 的 0.4.6 发布流水线；桌面端代码基线仍是 v0.4.4，仅由发布脚本保持版本字段一致。
- 机制：按 `git diff v0.4.5 v0.4.6` 逐文件移植，重叠文件语义合并；不做整仓 merge。理由与新约定见 `docs/adr/0008-sync-upstream-by-patch-not-merge.md`。
- 上游 0.4.6 在本范围内的实质内容：
  - 后端：OpenAI/xAI 图像解析在 `url` 与 `b64_json` 同时存在时两者都保留（下游优先用内联字节）；`textutil.SanitizeForTextColumn` 清理 trace 与 tool_call 列里的非法 UTF-8 / NUL；`golang.org/x/net` 升到 v0.60.0。
  - 前端：`message-agent-tool-step.tsx` 引入 `messageStreaming`，已结束回复里残留的 `calling` 步骤不再显示运行态与超长耗时；管理端日志标签支持横向滚动；两处 `Popover` 改为 `modal`。
  - 基础设施：Node 26.12.1（镜像不再内置 Corepack，改用 npm 安装 `packageManager` 指定的 pnpm）、`@types/node` 26、`engines` 收紧、`Makefile` 的 `version` 改走 `pnpm api:generate`、`sync-version.mjs` 同步 desktop 的 Cargo.lock。
- 版本策略：本 Fork 比上游更严——`engines.node` 写死 `>=26.12.1`，`go.mod` 写 `go 1.27.3`，Dockerfile 用 `node:26.12.1-bookworm-slim` 与 `golang:1.27.3-bookworm`。上游 0.4.6 只到 Go 1.26.10，Go 1.27.3 是本 Fork 额外的安全升级。
- 保留的 Fork 定制：`sync-version.mjs` 的 `web-backend` 模式（只同步 workspace/web/backend，不碰桌面端）继续保留。

## 环境事实（本机）

- Node `v26.12.1`；Go `1.27.3`（`GOROOT=C:\Users\Administrator\.g\go`，`go.exe` 在 `C:\Users\Administrator\.g\go\bin`，不在默认 PATH）。
- Go 模块代理 `proxy.golang.org` 在本机不可达（IPv6 超时），需用 `GOPROXY=https://goproxy.cn,direct`。
- 无 C 编译器：后端构建/测试统一用 `CGO_ENABLED=0` + `-overlay ../.verify/overlay.json`（替换 sqlitevec 与 dberror 的 cgo 实现）。
- pnpm 全局是 8.15.3，会重写 lockfile；必须用 `npx pnpm@10.17.0`。pnpm 默认 store 在 `F:\.pnpm-store`（工作区外，沙箱会拒绝写入），本地验证要加 `--store-dir=./.pnpm-store --cache-dir=./.pnpm-cache`。
