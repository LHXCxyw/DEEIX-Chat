## StreamIdleTimeoutMS 默认值 60s → 120s
- infra/llm/client.go defaultStreamIdleTimeoutMS=120000（运行时兜底默认）
- channel 创建/更新默认：service_upstream.go 两处 normalizeTimeout(...,120000)、service_user_upstream.go 120000

## 用户设置渠道编辑补充"流式超时"配置项
- 此前用户渠道（BYOK）创建/更新 API 与设置页均无 stream_idle_timeout_ms，用户无法调整流超时。
- 后端：application/channel/dto_user_upstream.go、service_user_upstream.go（创建读取 input、0 时默认 120000；更新按指针覆盖）、transport dto/handler 透传，响应体新增 stream_idle_timeout_ms。
- 前端：shared/api/user-upstream.ts DTO/payload 类型；settings-upstreams.tsx 表单新增"流式超时（毫秒）"字段（默认 120000，编辑回填）。
- 验证：go build 两个包 OK；前端 tsc 因本机 node_modules 未装依赖大量模块解析报错（预先存在），与改动无关。
## 项目工作区删除文件夹报"project file not found"修复
- 根因：① UI 批量删除用旧列表里的 PublicID，AI 改写文件后行被替换（WriteProjectFile 生成新 PublicID），旧 ID 404 导致整批中断；② agent 工具 project_delete_file 不支持目录路径（find 按精确路径匹配，尾斜杠不匹配），也不能连带删除子文件。
- 修复：前端 removeSelected 先刷新列表再匹配、单文件 404 跳过计入"已不存在"；后端 service_tool.go project_delete_file 支持目录路径（含尾斜杠），连带删除目录行+全部子文件，返回 deleted_count。
- 验证：go build conversation 包 OK；前端 tsc 仅剩环境缺依赖的预存报错。
