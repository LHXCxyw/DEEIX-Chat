## 流式响应 200"协议不兼容"诊断与修复
- 现象：上游 chat.completion.chunk 流在 reasoning_content 结束后中断，UI 报"上游返回 HTTP 200，但流式响应格式与当前协议不兼容"，最后一段仍是思考内容。
- 根因链路：backend `consumeOpenAIGenerateStream` 任一流内错误（idle timeout 60s / JSON 解析失败 / DSML 不完整等）经 `attachUpstreamDebug` 包装为 StatusCode=200 的 UpstreamError；`upstreamErrorSummary` 对 2xx 只输出笼统文案，真实 err.Message 被吞。前端 `hasSuccessfulStreamDebug` 也用通用 i18n 文案替换。
- 修复：service_message_context.go 新增 `upstreamStreamFailureCause`，2xx 摘要追加"原因："行（沿用 looksLikeRawSSEBody 过滤）；message-bot.tsx 折叠告警附加"原因："行。
- 疑似根因：思考结束→正文间停顿超过默认 60s 流空闲超时（defaultStreamIdleTimeoutMS=60000），可调渠道路由 StreamIdleTimeoutMS。
- 注意：本机跑 backend 测试因 sqlite-vec cgo 环境限制 setup failed（预先存在），gofmt 通过。
