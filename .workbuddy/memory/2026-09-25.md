## 图片生成 502 upstream.unavailable 问题分析

- 现象：qwen-image-2.1（Images Generations (OpenAI) 路由，openai_image_generations 协议）生成图片，SSE 事件 queued → running → error(502, upstream.unavailable)。
- 代码链路：`backend/internal/application/conversation/service_media_generation.go` StreamMediaImage；非流式（模型名非 gpt-image- 前缀）走 `infra/llm/openai_images.go` generateOpenAIImageGenerations → POST {BaseURL}/v1/images/generations。
- 错误包装：任何非限流/非空响应的上游失败统一被 `wrapUpstreamRequestError` → `ErrUpstreamRequestFailed`，`handler.go describeUpstreamRequestFailure` 固定输出 HTTP 502 + `upstream.unavailable`。**502 是通用包装码，不代表上游真实状态**。
- 排查入口：conversation_runs 表 run_b258acb17c4d456794f376f7840e4f1f 的 error_message（含上游原始信息）、SSE error 事件 debug 字段（脱敏上游快照）、后端日志。
- 伴生行为：失败时 MarkRouteFailure 会触发该路由熔断计数。

### 补充：画布成功 vs 聊天失败

- 画布与聊天走完全相同的后端链路：前端均调 `/media/images/generations/stream`（conversation.ts:1499），同一 StreamMediaImage / 路由 / 适配器，options 两侧都含 model.defaultOptions。
- 差异只剩：①画布模型默认取 imageModels[0]，实际可能不是 qwen-image-2.1；②prompt 内容（"画一个可莉" 可能触发上游 IP/内容审核）；③聊天参数面板额外设置 size/quality（DashScope size 格式为 "1024*1024"）；④时间差（上游间歇故障）。
- 定位法：conversation_runs 对比成功/失败两条 run 的 upstream_id、upstream_model_name、error_message；画布用同一提示词复测。
