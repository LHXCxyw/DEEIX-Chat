## 流内错误被误判为"200 协议不兼容"的真正根因
- 截图证实：上游（gpt-6.1-sol 渠道）SSE 流内发 {"error":{"message":"Our servers are currently overloaded...","type":"upstream_error"}}，HTTP 状态确实是 200（SSE 先建流后报错）。
- 后端本有 parseStreamUpstreamError 识别流内 error 对象，但该错误 JSON 是 pretty-print 多行格式，SSE 解析器丢弃无 data: 前缀的续行 → 事件被裁成非法 JSON → 误判为协议不兼容。
- 修复：openai.go SSE 消费器把无前缀续行拼回当前 data 事件、跳过 ":" 注释行；新增两个回归测试（多行错误负载、SSE 注释）。提交 eeea52c8。
- 修复后该错误将显示为"模型请求失败（HTTP 502）错误：Our servers are currently overloaded..."，并触发通道路由故障转移。
