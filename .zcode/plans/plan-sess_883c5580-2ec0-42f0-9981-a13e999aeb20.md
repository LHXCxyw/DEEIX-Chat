## 完整实现范围

### 1. 管理员按任务类型设置默认路由
在现有 LLM 全局设置中增加结构化配置 `default_task_routes`，值为任务类型到平台模型 ID 的映射：

```json
{
  "chat": 12,
  "image_generation": 23,
  "image_edit": 23,
  "video_generation": 31,
  "video_extension": 31
}
```

实现内容：
- 增加任务类型常量、严格 JSON 结构校验和模型状态/能力校验。
- 在默认路由解析中优先使用管理员显式配置；未配置的任务继续使用现有按排序扫描的兼容 fallback。
- 显式配置的模型不可用、不支持任务或没有有效路由时返回明确错误，不静默切换到其他模型。
- 模型停用、删除、移除能力或删除路由时同步清理/拒绝无效默认映射。
- 模型更新和默认映射更新放进同一事务，避免模型配置与默认路由部分成功。
- 图片生成、图片编辑、视频生成、视频延展在请求未指定模型时也使用对应任务的默认路由；显式模型仍优先。
- 保持设置 seed 的向后兼容默认值 `{}`。

### 2. 管理后台模型配置界面
- 在管理员模型编辑表单中增加“默认任务路由”复选项/选择项。
- 只展示当前模型 `kinds` 支持的任务类型；移除能力时自动取消对应默认项。
- 创建模型阶段不显示默认任务配置，待模型来源绑定后在编辑页设置。
- 扩展管理员模型 DTO、PATCH 请求、响应初始化和中英文文案。
- 增加默认路由配置的纯函数/组件测试，覆盖 payload、能力变化和不可用模型场景。

### 3. 管理员用户渠道预设管理
保留当前使用 `llm_settings` JSON 存储的方案，但修正管理员与用户查询语义：
- 管理员 GET 返回全部预设，包括停用项。
- 用户 GET 只返回启用且字段有效的预设。
- PUT 做 ID 唯一性、字段必填、URL、兼容类型、协议默认 JSON 对象校验。
- 删除采用停用而非物理删除，保证已创建渠道的配置快照不受影响。
- 增加管理员 API 类型和客户端封装。
- 在“管理后台 → 上游渠道”页面增加独立的“用户渠道预设” Sheet/面板：
  - 列表、新增、编辑、启停、拖拽排序、删除/停用确认。
  - 表单包含名称、预设 ID、URL、兼容类型、协议默认配置。
  - 保存采用整表 PUT，保留未选中的停用预设，避免数据丢失。
- 增加默认预设 seed 或清晰的空列表状态。

### 4. 用户自用渠道与模型同步
- 用户创建渠道选择预设后，只需填写令牌；预设的名称、URL、兼容类型和协议默认值作为创建时快照写入渠道。
- 自定义渠道继续兼容。
- 修正创建请求校验和错误映射：无效 `preset_id` 返回 400，不返回 500。
- 用户模型同步按 `(用户、渠道、远端模型 ID)` 做真正 upsert，避免改显示名后产生重复记录。
- 重复同步恢复 disabled 模型；保留用户修改过的显示名、能力覆盖和参数，明确只刷新远端身份/状态。
- 管理列表查询返回用户自己的 active 与 disabled 模型，包括 inactive 渠道下的记录；聊天与画布目录继续只返回 active 模型且要求渠道 active。
- 修复 GORM 更新零值问题，确保 `capabilities=""`、`priority=0`、`weight=0` 能真正落库。
- 单条创建接口统一使用项目 API response envelope。
- 用户能力配置要求顶层 JSON 对象，并复用已有能力语义校验。
- 平台模板查找只忽略明确的 not-found，其他数据库错误向上返回。
- 用户模型运行时映射继续传递自身 capabilities，使 defaultOptions、lockedOptionPaths、媒体参数和原生工具配置生效。
- 修正模型表格空态/加载态的列数。

### 5. 数据库与仓储
- 增加用户模型按远端模型 ID 的部分唯一索引或等价查询约束，并设计旧数据重复记录的迁移处理。
- 扩展仓储接口，区分管理列表与可路由列表，避免用一个 active-only 查询承担两种语义。
- 增加用户模型 upsert、状态恢复、能力显式更新方法。
- 不覆盖工作区中已有的无关未提交改动。
